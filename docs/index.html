What makes it different

Many clusters, many windows, many tabs

Every cluster gets its own tab with a color-coded chip and a live connection-status ring. Open additional OS windows — each an independent workspace with its own tabs, navigation, and namespace. Drag a tab between windows to reorganize, or tear one off into a new window; the connection travels with it.

Your whole fleet on one screen

Open more than one cluster and an All Clusters tab appears: aggregated CPU, memory, and pod usage with history sparklines, a summary card per cluster sorted by recent errors, and a merged, filterable event feed spanning every connection — complete with savable filter presets and a reason heatmap.

See how it all connects

A whole-cluster topology graph shows workloads, pods, services, and the relationships between them, with animated packets flowing along connections. Zoom, pan, rotate the flow, and fit to screen; click a node to highlight its entire pipe. Refreshes on a configurable interval and pauses when you look away.

Operate, don't just observe

KubeKubeDashDash goes beyond read-only browsing. Evict, force-delete, or open a shell into pods; cordon and drain nodes; scale and rollout-restart workloads; trigger or suspend CronJobs; approve or deny certificate signing requests — each from the resource's detail panel, every destructive step behind a confirmation dialog.

It stays a browse-and-operate tool: no blanket resource creation and no free-form YAML editing.

Jump anywhere with ⌘K

Press ⌘K / Ctrl K for a fuzzy finder that scores on subsequence matches — jump to any screen, switch between open clusters, or navigate straight to a namespace, a cached pod, a node, or a discovered CRD, without lifting your hands off the keyboard.

Logs and a real pod shell, docked in

Stream pod logs in a resizable bottom drawer (⌘J / Ctrl J) — one tab per container, per-tab text filter with match highlighting, and a persistent tab for the app's own diagnostics. Need to get in? Open an interactive kubectl exec shell that keeps its scrollback across tab switches.

Detail panels that go deep

Many kinds get resource-specific tabs. Roles and RoleBindings resolve their effective rules and subjects, ResourceQuotas show live usage bars, EndpointSlices link straight through to the Service that backs them, and Deployments draw their full ownership graph.

Your CRDs, treated as first-class

Custom resource definitions are discovered automatically when you connect, then listed in a dedicated, searchable sidebar section grouped by API group. Pin or hide them per cluster, browse them through the same table and detail UI as built-in kinds, and find them in the command palette and the topology graph.

Light, dark, or follow the system

Built on Material 3 with bundled Inter and JetBrains Mono fonts for consistent rendering everywhere. Pick light, dark, or system — every screen, panel, chart, and graph adapts. Status badges pair color with a glyph, so state stays legible either way.

Coverage

Every resource kind, one consistent interface

Sortable, live-updating tables — via Kubernetes watch where available, polled otherwise — with keyboard navigation, truncation-on-hover, and a side panel that pairs an Overview with read-only, syntax-highlighted YAML. The same UI covers everything from core workloads to admission webhooks and any CRD on your cluster.

First launch on macOS. The build isn't notarized yet, so Gatekeeper will block a normal double-click. Right-click the app in Applications → Open → Open once, and macOS remembers it from then on.

Verify your download. Each installer ships with a matching .sha256 on the releases page. Other architectures (e.g. Apple Silicon native, Linux non-Debian) can be built from source with JDK 21.

You'll need a ~/.kube/config with at least one cluster. Connecting to EKS, GKE, or AKS uses your existing aws, gcloud, or kubelogin/az CLI; CPU and memory figures need a Metrics Server.

No cluster handy? Try the demo.

Pick Demo Cluster in the connection picker and explore every screen against a built-in simulator — synthetic nodes, pods, seeded CRDs, live-updating metrics, and a steady trickle of events. No kubeconfig required.
